# Total Commander 菜单与标签维护

直接修改用户选定的 TC 配置，交付可用入口和原文件备份。优先沿用现有菜单、标签模板与图标，不因一次新增项目重新设计整个工具栏。

## 定位配置

- 用户已给出安装目录或文件时，以其为准。可将用户已确认的布局记录在 [references/personal-layout.md](references/personal-layout.md)，其中初始内容只是示例；只有路径和现有菜单吻合时才应用。
- 其他机器先查看 TC 进程的可执行文件位置、`COMMANDER_PATH`、快捷方式或用户指定目录。多个安装实例不能凭修改时间替用户选择；仍无法确定时再询问安装位置。
- 读取实际主工具栏配置；常见入口是安装目录 `Default.bar`，但用户可能使用其他文件。必要时只查 `wincmd.ini` 中的 Buttonbar、RedirectSection 等相关键，跟随重定向，不遍历输出整份用户配置。
- 列举目标菜单目录的 `*.bar` 和标签目录的 `*.tab`。`.br*` 是图标缓存，不作为文本读取；`.bak` 和备份目录不纳入现用菜单分析。

## 修改约束

- 先读目标文件、调用它的菜单及最接近的模板，再编辑。修改前复制原字节到安装目录下 `Backups/<时间-任务>/` 或用户指定的备份目录，记录原相对路径。
- 用户直接要求维护配置即授权必要的本地修改。无需为普通新增、修正反复确认；删除整个标签、归档菜单或大幅重排须属于本次整理范围。一次新增不顺带清理其他入口。
- TC 内部引用采用 `%Commander_path%`。建议标签放 `Tab`、菜单放 `Bar\xpl`、自定义图标放 `PIC`；已有安装沿用用户确认的实际目录布局。已配置的主工具栏可留原位，不为统一目录擅自修改运行中 INI。
- 业务目录保留真实绝对路径，例如书稿、培训和源码目录；不把它们误写成 TC 安装目录的相对路径。
- 保留原编码、BOM、换行、标签选项、左右面板及选中索引，除非用户明确要求修改。新文字必须能以原编码无损写回；不能表示时再选择 TC 支持的 Unicode 编码并说明。中文老配置常见 CP936，不能依赖 PowerShell 默认 UTF-8。
- 不自动关闭 TC、执行菜单中的业务命令或修改用户资料。写入前比对当前字节与读取快照；TC 或用户同时修改了文件就中止覆盖，重新合并。

## 常见任务

### 新增菜单与标签

1. 找到同类标签作为模板；用户要求“图标和某项一致”时，读取并复用那一项的 `buttonN`，不要凭截图猜图标文件。
2. 为新标签使用独立文件名，已存在则先核对内容，不覆盖人工修改。替换主目录和对应标题；模板内重复出现的同项目根目录也应核对。共享课件、桌面、下载等继续保留；项目子目录不能仅靠全局字符串替换迁移。
3. 在明确锚点后插入菜单项，未指定时放入同类项目附近。新增 tab 页时，在对应面板下追加连续的 `N_path`、可选 `N_caption` 和相应 `N_options`，默认保持原选中项。
4. 菜单 `Buttoncount` 包含分隔线；按钮按 1 起编号。插入和删除必须一起移动该按钮的所有字段，包括 `button/cmd/menu/iconic/param/path` 及已有其他字段，不丢失未知字段。

示例（编号仅用于说明，实际按原文件插入位置调整）：

```ini
button19=%Commander_path%\PIC\培训.ico
cmd19=OPENTABS %Commander_path%\Tab\示例培训.tab
iconic19=0
menu19=示例培训
```

`.tab` 中 `[activetabs]` 和 `[inactivetabs]` 的页号分别从 0 开始，各自有 `activetab`。不要跨面板替换同号键；两个面板不等于固定左、右位置。引用文件名含空格时保留/使用 TC 命令所需的成对引号。

### 目录迁移与菜单整理

- 先确认新目录存在并与旧目录用途一致。以最长、最具体的目录映射优先匹配，不能简单替换工作区根目录后假设其子结构没变。
- 保留无法核实的历史路径，列出“缺失目录 / 离线映射盘 / 压缩包内部路径”等实际状态。不能为了检查全绿，把旧项目改指向另一个项目或删掉书签。
- 重复入口要比较命令和标签内容；同名、相似图标不等于重复。用户要求整理时可以合并分类，但保留要求的入口和所有仍需使用的目标。
- `em_*` 命令需要检查当前 usercmd 定义和 INI 重定向，不能仅凭它不是 `OPENTABS` 就判失效。归档旧菜单前检查全部现用 BAR、相关 INI/MNU 中的调用关系。

### 图标修正

- 优先复用 `PIC` 中合适的现有 ICO；新取得的自定义图标先保存到 `PIC`，再使用 `%Commander_path%\PIC\名称.ico`。
- 需要时从本机合法安装的软件或 Windows 资源提取 ICO。PNG 改扩展名不是 ICO；转换或提取后验证可读取，必要时制作临时预览查看。
- `shell32.dll,N`、`wcmicons.dll,N` 等原生资源引用本身可以有效；区别原生系统图标与用户自定义图标，不强行复制全部系统资源。
- 不通过写死某个 EXE 的安装路径来充当自定义菜单图标，也不随 Skill 打包转发 TC 的程序、授权文件或第三方图标库。

## 修改后检查

先记录修改前基线，再复查修改后的同一范围。附带的脚本只读配置，不修改菜单、标签、缓存或用户资料：

```powershell
$check = '<技能目录>\scripts\Test-TcConfig.ps1'
$result = & $check -Root '<TC安装目录>' -MenuDirectory 'Bar\xpl' -TabDirectory 'Tab' -LegacyCodePage 936
$result | ConvertTo-Json -Depth 6
```

其他用户未确定 ANSI 编码时不传 `-LegacyCodePage`：脚本先识别 BOM / 有效 UTF-8，再按本机 ANSI 代码页读取；不确定时显式指定。`-MenuDirectory`、`-TabDirectory` 支持当前安装布局内的相对目录。可选 `-Strict` 在发现配置结构错误时抛错；旧业务目录缺失单独列在 `UnresolvedPaths`，不等于菜单语法错误。

- 检查数量、连续编号、重复键、选中索引、菜单目标与图标文件、绝对 TC 内部引用；对比未修改项与备份一致。为本次新增的路径做存在性检查。
- 脚本不会展开 `em_*`、执行程序、连接 NAS、读取压缩包条目或证明图标资源索引有效；这些项目会说明核验边界。不能把脚本零结构错误说成全部业务路径有效。
- 如果发现错误，只修本次造成的问题或用户明确要求的范围；已有问题独立报告。若看到 TC 覆盖了配置，停止重复写入，保留备份并协调保存状态。
- 简短交付：新增/修改的入口、文件链接、备份位置、实际检查结果，以及仍未核实的路径。提示重新展开菜单或重新载入标签；没有操作真实界面就不要声称已实机验收。

维护脚本可用 `scripts/Test-TcConfig.SelfTest.ps1` 在临时目录运行最小自检，不接触真实 TC。
