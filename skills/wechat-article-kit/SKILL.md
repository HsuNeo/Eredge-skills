# 微信公众号文章排版与封面

**通用的是排版、复制体验和交付规格。写什么、用什么口吻、配不配图，由本篇内容和作者决定。** 一份纯文字稿就可以完成制作。

## 先确定本次交付

- **完整制作**：在文章目录交付《文章原题》.html 和一张可直接上传的公众号横版 JPG 封面。正文用到配图时，另放一份与网页一致的“配图”目录。纯文字文章直接交网页和封面。完整图文稿默认把同一张封面放在正文第一段上方，并保留独立 JPG。作者指定只用作后台封面时，按要求省去正文首图。
- **分步制作**：用户说“先给我文字”，只给标题、署名（如有）、摘要和正文。已有定稿并要求排版或制作素材，直接按稿制作。只补封面、只改排版、只要 HTML 时，按本次指定的范围更新。
- 用户点名某个系列、参考页或固定版式，就采用对应要求。例如《造价工程师的自我修养》连载已有专用制作流程。

## 文字和素材听从文章内容

- 作者要求起草或扩写时，先看读者是谁、要让读者读懂或完成什么。观点文可以从判断和依据写起，教程适合按操作顺序展开，通知把时间、对象和要办的事放在前面。随笔和回忆沿用作者的声音；第一人称只在作者口吻和文体合适时使用。标题、摘要应能独立用于公众号，摘要优先沿用作者定稿，未提供时从正文提炼。
- 以最新人工稿和作者的明确纠正为准。“只排版”保留原文；“只改错别字”只修唯一可判定的笔误，核对标题、摘要、各级标题、段序和正文，另行提示实质疑点。合并素材时区分作者亲历、转述与有来源的事实。作者要求用自己的口吻时，以本人提供的经历、疑问和判断开场，遇到行业概念先用读者听得懂的话解释。去模板化编辑可用已安装的 `natural-writer` 技能（可选）。正文尽量一段讲一件事，并列事项用真实的有序或无序列表。
- 按读者的需要选图。软件操作可以用界面截图，数据比较可以用表格或图表，活动记录可以用现场照片，工程题材按需用图纸或模型。适合纯文字表达的内容直接排文字。只加工发布副本；有图时逐张查看内容、方向和来源，紧跟有关段落，必要时加简短图注。宽图、小字截图在手机上看不清时，优先裁取重点或拆图。正文用到的每张发布图片和封面均以 **≤1,000,000 字节** 为制作规格。

- 分析型稿件可采用咨询报告式排版。用白底、深海军蓝和少量强调色，主标题与各级章节标题居中，段落和列表左对齐。数据图表按原始可核查数据重绘。柱状图从零起画，横向比较的分项图保持同一量尺。份额可用饼图或环形图，注明统计范围并核对合计。作者偏好立体效果时，用轻微侧面或阴影增强层次，避免透视改变柱高或扇区比例。
- 两个时期的表格优先用同一来源、同一统计口径，区分历史统计、回溯估算和预测。关键数据及来源放在相邻位置。手机端优先使用列数少的真实表格；需兼顾公众号粘贴保真时，另备同数据的表格图片。

## 排版和 HTML 网页

1. **阅读层级**。主标题居中醒目，署名按作者提供的信息显示。正文左对齐，通常 17px、行高约 1.9；用段间距分段，小标题、步骤列表、引用和图注按内容使用。标题色随文章、品牌或指定参考页调整，保证与背景的对比。短文可直接分段。
2. **顶部操作区**。显示摘要，提供“复制标题”“复制摘要”“复制正文”和“375px 手机宽度预览”，按钮有操作反馈。标题与摘要复制为纯文本。正文同时复制富文本和纯文本，包含正文中的排版和配图；工具栏、摘要、重复主标题留在正文之外。封面作正文首图时，它在可选、可复制的正文范围内，手动选中图片和一键复制正文都可带上。
3. **独立离线文件**。正文使用元素级内联样式；用到的图片以 data URL 内嵌，不依赖相册路径、网络字体、CDN 或本地服务器。把 HTML 单独移到别处也应能打开、阅读和复制。
4. **公众号正文中的网址**。外部资料、下载和购买入口用“来源或用途＋完整 HTTPS 网址”的可复制正文文字，建议网址单独一行，行末不加标点。清单可用普通段落 `p`，用换行分隔说明和网址。粘贴 HTML 超链接能否保留、跳转取决于公众号账号权限和发布环境，默认按读者可复制网址到浏览器打开处理。引用已发布的公众号文章时，如需点击跳转，在公众号后台用“超链接”或“查找文章”插入并预览核对。
5. **使用随附版式**。制作人可以在临时目录整理 UTF-8 清单，用 [build_article.py](scripts/build_article.py) 和 [HTML 模板](assets/article.html) 生成网页。作者照常给稿即可。清单按正文顺序写 blocks；支持段落 p、标题 h2/h3、列表 ul/ol、引用 quote 和图片 image。可选字段包括署名 `author`、十六进制标题色 `accent`，以及报告版式 `layout`（设为 `report`）。用 `cover` 对象放入正文首图，字段为 `src` 和 `alt`，路径相对清单。省略 `cover` 可仅交付独立封面。下面的纯文字稿可以直接生成网页。

```json
{
  "title": "这次读书会怎么参加",
  "summary": "读书会的准备事项和当天的交流安排。",
  "blocks": [
    {"type": "p", "text": "这次读书会，每位参与者可以带来一个最想讨论的问题。"},
    {"type": "h2", "text": "参加前的准备"},
    {"type": "ul", "items": ["读完本期选定的章节", "记下一段想和大家讨论的话"]}
  ]
}
```

在技能目录运行 `python scripts/build_article.py 稿件.json "文章原题.html"`，输出到已准备的临时目录。有配图时插入 `{"type":"image","src":"配图/01.jpg","alt":"画面内容","caption":"需要时填写图注"}`，路径相对清单，采用已优化的 JPEG 或 PNG。引用块用 `{"type":"quote","text":"原文引语"}`。有复杂表格或指定版式时可在工作区扩展版式，仍需实测手机阅读与富文本复制。

## 最后生成独立封面

完整制作时同步交付 **1880 × 800、约 2.35∶1、单张 ≤1,000,000 字节的 JPG**。用已定标题，按语义分行，核对完整题名和署名。可以采用纯文字排版、主题色块、插画、截图、图表或照片；选择能让读者在缩略图上认出主题的方案。标题易读、主体清楚比堆装饰更重要。独立 JPG 用于上传后台封面。需要兼作正文首图时，HTML 使用同一文件嵌入。

[make_cover.py](scripts/make_cover.py) 使用 Python 和 Pillow，可直接生成下列两种封面。输出文件名使用新路径，署名可省略。

```text
python scripts/make_cover.py "文章完整标题" "公众号封面.jpg"
python scripts/make_cover.py "主图.jpg" "文章完整标题" "公众号封面.jpg" --author "作者署名"
```

有图时可用 `--focus X Y` 调整裁切焦点；两种模式均可用 `--line` 指定标题换行、用 `--font` 指定中文字体。以约375px宽查看横幅，再预览居中方形裁切，确保核心题词和有意义的主体留在画面中。

## 核验和存放

- 离线打开最终 HTML，实际点三种复制和手机宽度切换，核对标题、摘要、正文及其内联排版。图文稿逐张核对内嵌图片和数据来源。封面前置时，确认它位于第一段上方且复制正文会带上同一张图。按编辑稿核对段落和列表。在375px下检查无横向溢出，图片、图表文字和图注可读。另开封面检查尺寸、大小与缩略效果。有外部网址时，在复制后的正文里核对完整网址仍可见、可复制，手机宽度下可自然换行。本地验证结果与公众号后台的实际粘贴效果分别说明。
- 用户指定位置优先。未指定时在当前工作区为文章建立独立目录。HTML 用文章原题；封面按“文章简称＋公众号文章封面＋YYYYMMDD＋V序号.jpg”命名；有配图时按正文顺序整理。只留终稿的任务先检验新版，再清理已确认的本篇旧生成物与测试文件，保护原稿和人工修改。
- 交付可点击的 HTML、封面及实际存在的配图目录，按工作区要求报告文件大小和空间变化。上传、发布或改动线上草稿需另有作者授权。
