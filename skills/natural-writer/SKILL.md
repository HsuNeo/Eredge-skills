# 自然写作与去模板化

让文字符合作者、读者和使用场景。“去AI味”指改善表达，不鉴定作者身份，也不承诺 AI 检测分数。

## 确定范围和声音

- 先读完原文，遵守用户指定的用途、受众、字数、语气、格式和保留内容。默认做必要修改；轻改不升级为整篇重写，只问问题时不擅自重写。
- 用户提供作者样文时，参考其用词、句长、段落起笔、衔接和情绪强度。只借表达习惯，不把样文中的事实、经历或观点搬进新稿。没有样文时延续原稿声音，不擅加“我”、幽默、情绪或立场。
- 需要原文却尚未取得时，先查看用户明确指向的可用文件或上下文；仍无原文再索取。明确要求从零起稿时依据所给资料写，不冒称改写。

## 事实和含义优先

- 保留名称、数字、日期、单位、术语、引用、链接、适用条件、功能边界、作者立场及行动要求。尤其不能把“超过3000”改成“3000”，把“计划”改成“已经”，把“可能”改成“必然”。
- 精简“可能、大概、或许”等叠加表达时，保留实际不确定性；区分空套话与有意义的“截至某日”“仅适用于”“尚未验证”。礼貌、风险提示和合规表述按用途保留。
- 具体内容只能来自原文、用户资料或已核实的来源。没有依据就删去无信息的夸大，或说明缺什么；不靠编造功能、案例、采访、数据、用户评价或亲测经历填空。
- 不把“专家认为”偷偷改成确定事实，也不补造专家或文献；核心论点缺来源时单独提示待核实。润色不等于核查，发现事实矛盾或疑点时说明；有依据更正时交代依据。
- 对引号内原话、法规条文、公式、代码、路径和固定界面名称，默认不改内容；需要改动引语时注明为转述，不继续冒充原话。

## 按问题编辑，不按禁词表替换

先看逻辑和重复，再改词句。已有清楚的结构不为追求变化而打散。以下是检查线索，出现某个词或句式本身不构成错误。

| 问题 | 编辑取舍 |
|---|---|
| 空泛赞美、拔高意义、广告口号 | 删去无信息评价，用已有资料中的动作、用途或限制说明，不制造新事实 |
| 模糊权威、句尾强加意义或因果 | 保留可靠归因；检查“彰显、反映、确保、从而”等后面的判断是否有依据 |
| 宣告和套式结构 | 压缩“下面深入探讨”、标题后重述标题、无内容的展望与总结；真实需要的背景和收束保留 |
| 机械对比、排比和重复句式 | 只改空转的“不是X而是Y”“不仅而且”、强凑的三项或“从X到Y”；真实对比、完整列举和合理顺序保留 |
| 冗长、翻译腔、无主体表达 | 理清谁做什么，能用“是、有、可以”就不绕写；主体未知或不重要时不硬造施事者，也不一律改主动语态 |
| 同义词轮换和术语漂移 | 同一对象用一致名称；可删除重复内容，不为避重而更换专业术语 |
| 排版和聊天残留 | 去掉混入正文的“当然可以、希望有帮助”等回复话术；减少纯装饰的加粗、表情和碎片化分行，保留有用的标题、列表与提示 |

自然调整长短句和段落，不设固定句长或项目数，不为“像人”制造语病、跑题和错别字。中文保留正常中文引号与标点；英文遵守语法、连字符和出版风格，不机械套用中文习惯。标点、连接词、三项列表、中立语气和精练句子都不是禁用项。

## 场景取舍

- 公众号、短文、口播：尽早进入具体问题，便于阅读或说出口。已有真实场景和个人判断可保留；不虚构故事，不固定追加关注、点赞、收藏或金句。
- 产品说明、帮助文档：讲清入口、操作、结果和限制；保留按钮名称、截图/GIF位置、链接、必要步骤以及项目要求的标题、编号和图标。不把功能介绍写成效果保证。
- 正式通知、报告、专业材料：保留对象、时间、地点、要求、专业术语及必要礼貌。可以严谨、中立，不强行改成聊天口吻。

需要判断边界或参考改写尺度时，读 [边界与改写示例](references/examples.md)。

## 交付前检查和输出

在内部对照原稿检查：事实与限定是否遗漏或变强，是否增加了无依据内容，作者身份和立场是否变化，原有格式与修改范围是否保留。再通读检查重复、绕口和过度整齐的句式；没有问题的地方不用再改。

默认只给最终文字。要求对照时给原文、修改后和简短原因；要求审阅时说明具体问题。需要核实的疑点与正文分开写。不默认输出草稿、审计过程、自评分或多轮版本；用户明确要求时再提供。
