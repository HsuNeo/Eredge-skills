# 工程施工动画制作

接到请求先确定本次交付终点：预览片、指定分镜修订、正式成片、已有成片加字幕，或发布素材。用户只要其中一项就做到该项。要求一次做完时，连续执行到指定终点；只有必要源文件缺失、打不开或确实无法继续时才询问。用户明确说“预览后等我确认正式渲染”，就以交出预览为本轮终点。

## 接续和重建

- 新对话先读项目根目录的《项目说明.md》、对应版本的生成脚本、分镜和时间轴表、SRT、配音文件；实际打开工程，探测 MP4 和音频的轨道、时长、帧率。多个同版本 MP4 要查清哪个有外挂、软字幕或烧录字幕，根据本次要求选择母版。
- 有参考视频时先逐段抽帧，运动和遮挡看前、中、后帧。把工序、构件比例、吊放或浇筑方向、机位、镜头切换点和时长对应到分镜。参考片里的名称、单位、Logo 和用户品牌按本项目约定处理。桥梁原项目的具体取舍见[续作例](references/bridge-project.md)。
- 建立可编辑三维模型，布置施工场景，再做分镜动作与相机。模型、材质、关键帧、镜头、字幕和时间线均由 Blender Python 或配套脚本重建。尺寸、坐标、镜头位置和起止帧集中管理，每段脚本注明分镜编号及工序，物体、相机、动作带同一编号，如 `S03_镜头`。记录 Blender 版本、运行命令与相对依赖；贴图、配音打包到工程或随件交付。在独立路径后台重开或重建验证。
- 首次预览按需要用 Workbench 或低清渲染完整 MP4，保留独立 SRT。按分镜提修改时只改对应脚本和关联时间轴，只重渲受影响镜头，之后按要求合成。只改文字、时长和节奏时，保留模型造型、材质、机位。全片画质升级时才调整获准的光照、材质、细节和原生渲染分辨率；先检查典型样帧，核对工序主体清晰、运动可读。复刻默认沿用参考片分辨率、帧率；用户指定升级参数时采用新规格。
- 把分镜表、脚本段落、参数含义、品牌字位置、当前总时长、版本、变更分镜和复建指令写回《项目说明.md》。项目目录遵循本机约定，通常在 `E:\AI-Work\projects\项目名\`，成品进 `output`，中间件进 `scratch`。保留人工修改及旧版，交付文件按项目名＋文件名＋YYYYMMDD＋版本号命名，同版派生文件加“含字幕”等用途名。收尾清点文件及大小，仅清理本次可重建的临时文件，报告空间变化。

## 语速、配音和时间轴

1. **先算基线。** 逐条计算“实际朗读字数 ÷ 该条字幕时长（秒）”，同镜多条分别算。空白和标点不计，数字、单位、范围按实际普通话读法展开。例如 80% 按“百分之八十”计 5 字。目标 **4～5 字/秒**，上限 **5.5**。用未四舍五入的结果判定，列出全部超标条目。原字幕、原录音、原时码都保留可追溯关系；后续修改均以这张表为依据。
2. **先精简，再调时长。** 删套话、重复修饰和“进行……工作”等空转句。逐条核对工序名、材料、数字、单位、关键动作、条件和先后关系。指定品牌句原样保留。每条字幕末字后不加标点，包括省略号；句中标点照常，百分号、度号及必要的技术符号保留。SRT、软字幕及 Blender 烧录文字均取自同一份定稿。
3. **用实测声音定时。** 按定稿用指定音色、正常语速重新生成超标段；凡改词、旧声曾加速或无法核实为原速的，也重新生成。可复用文字一致、有正常原声依据的录音。记录合成参数和来源，检查合成、后期与时间线播放倍率。不得加快合成、变速、裁掉字尾或压短句中停顿来塞进旧时长。先量每条音频有效时长，再留自然收句空隙；即使参数为原速，实际仍过快也应重读。
4. **声音决定画面。** 精简后仍超标或原段容不下正常配音，按需要等比例调整该段关键帧、运镜、停留。若所需拉长超过原段 **40%**，按语义与可见动作拆成前后两条字幕、两段配音、两拍动画。拆后的文字再定稿、配音再实测。保持运动连贯，避免慢动作发飘或长时间静止。其后各镜头顺延，允许片长增加，其他段保持原速。
5. **一次定表，三处同改。** 表内分别记录镜头帧区间、每条字幕区间、配音起点和实测时长。派生 Blender 动作及镜头时间轴、SRT 时间戳、声音条位置。以帧和采样为准，最后导出 SRT 时才舍入毫秒。对照表至少包含分镜编号、原字幕、新字幕、原时长、新时长、改前语速、改后语速、处理方法（精简／放慢／拆分，可组合）；拆分保留原序号与拍次，统计原时长时去重。
6. **正式渲染前复核。** 每条显示区间的语速均须 ≤5.5，所有配音为原速；对照原声和实测朗读速度，排除“延长空白但实际仍说得快”。逐句查文字、句尾、时间边界、重叠和截尾，抽看拆拍交界。可用[逐条校验脚本](scripts/check_timeline.py)对定稿表和 SRT 作只读核验，表的字段与用法见[时间轴校验](references/timeline-check.md)。未通过先修对应段，再渲染。

## 配音与字幕交付

| 用户要求 | 做法与验收 |
| --- | --- |
| 有配音、字幕单独给 | 配音封装进 MP4，讲解字幕既不烧录也不写入字幕流；独立 UTF-8 SRT 与 MP4 在同一目录，文件名逐字相同，仅扩展名不同 |
| “什么都不改，只把字幕也嵌入” | 从已配音的无字母版另存含字幕 MP4，复制原视频流、音频流，内封简体中文可选字幕轨并设默认开启。播放器可关闭，无需重渲 |
| 明确要烧录、压字或任何播放器都看得到 | 从干净画面按主表叠字，再导出。逐条对照 SRT，抽帧检查字幕安全区、中文字体和换行。已有硬字幕且要求无字时，回到无字母版或工程重新输出 |
| 只要配音文件 | 按定稿字幕生成独立音频，从视频零点对齐，保留句间间隔，文件格式和返回方式服从本次要求 |

用 ffprobe 查看成片实际轨道、时长和起止时间；解码检查画面、原声与末句。仅重封装时分别比对输入输出编码视频包、音频包哈希和时间戳；抽出内封字幕，与 SRT 逐条比对正文和起止时间。字幕轨缺失不能单独证明画面无字，还要抽看对应画面。模型上的商标、片尾标语与讲解字幕分别检查。

## 简介、标签和双封面

仅在用户要发布素材时执行。按定稿 SRT 写一段观众能读懂的简介，点出片中实际出现的几道工序。制作说明按真实过程写明“建立模型 → 创作场景 → 制作动画 → 根据字幕生成语音”；确实全程由 AI 制作且无手工修改时，按用户要求明确写出。标签选工程类型、代表工序、动画形式和 AI 制作等相关词，保存可复制的简介与标签。

优先从成片取能认出工序的关键帧作视觉参考，以同一中文标题分别构图 **3:4 竖版**和 **4:3 横版**，如 1080×1440、1440×1080；按手机缩略图检查标题、构件、吊装连接和裁切边界，实际打开两张图核对像素比例。只要简介与封面时即可交付这些文件。
